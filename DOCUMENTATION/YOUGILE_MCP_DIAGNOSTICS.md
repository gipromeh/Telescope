# Диагностика MCP YouGile через GitHub Actions

Диагностический workflow вручную подключается к YouGile MCP по Streamable HTTP, выполняет `initialize`, уведомление `notifications/initialized` и `tools/list`. Он выводит имена обнаруженных инструментов и отмечает, найдены ли операции списка, создания и обновления для Базы знаний по именам MCP-инструментов. Дополнительный флажок `inspect_kb_pages` выполняет только вызов чтения `kb_list_pages`; содержимое страниц не выводится; если обязательные параметры допускают `null`, workflow передаёт `null`; иначе в логах отображаются только имена, типы и описания параметров. Вызовов инструментов записи нет.

## Настройка GitHub Actions Secrets

В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:

| Имя секрета | Значение |
| --- | --- |
| `YOUGILE_MCP_URL` | HTTPS URL конечной точки MCP, выданный YouGile |
| `YOUGILE_MCP_TOKEN` | Новый Bearer token YouGile |

Не передавайте токен в чат и не помещайте его в файлы репозитория. Если токен ранее показывался на снимке экрана, сначала отзовите его в YouGile и сохраните новый. Workflow отправляет токен только в заголовке Authorization и не печатает его или URL.

## Запуск

1. Откройте **Actions → YouGile MCP Test**.
2. Нажмите **Run workflow**, выберите `main`. Для обычной проверки оставьте `inspect_kb_pages` выключенным. Чтобы отдельно проверить чтение списка страниц, включите этот флажок.
3. Откройте завершившийся запуск и шаг **Diagnose YouGile MCP**.
4. Передайте владельцу проекта только список имён инструментов и их статусы. Не включайте секреты в issue, PR или логи.

Результат подтверждает наличие инструментов и, при включённом флажке, успешность read-only вызова списка. Он не печатает заголовки или содержимое страниц и не подтверждает возможности записи. Перед любой публикацией документов необходимо отдельно проверить фактические инструменты и согласовать безопасную схему вызова.
